# Design

## Scope

Validates a `json.Value` against a JSON Schema draft 2020-12 schema and
reports every failure as an `Issue` with two JSON Pointers, the instance
location and the keyword location, after the specification's "basic" output
format. `compile` and `compileWith` prepare a schema once, `validate`
returns the `Result`, `isValid` answers yes or no, and `describe` renders a
result as text. The deck is pure computation: no I/O, no network, no
capability.

Not in scope:

- **Fetching anything.** A remote `$ref` resolves only through a `Registry`
  the caller fills with `register`; an unreachable reference is a schema
  error.
- **Older drafts.** Draft 2019-09 and draft-07 are not implemented, apart
  from draft-07's `dependencies`, which is honoured. A `$ref` to an older
  meta-schema is evaluated as 2020-12.
- **Schema generation, defaults and coercion.** The deck validates; it does
  not fill in or convert values.

## Decisions

- **A deck, not core.** JSON Schema is several live drafts (draft-07,
  2019-09, 2020-12, a successor in progress) whose churn would force
  breaking core releases; remote references mean I/O and trust decisions a
  pure-value library should not make; and `pattern` is ECMA-262 while
  Jennifer's `regex` is RE2. Draft 2020-12 came first because MCP tool
  schemas and structured-output definitions use it.
- **Compile once.** `compile` refuses anything but an object or boolean,
  takes the base from the root `$id` (or `DEFAULT_BASE`), indexes every
  `$id`, `$anchor` and `$dynamicAnchor`, and walks every resource the schema
  reaches to cache reference targets, translated patterns and per-resource
  vocabularies. Indexing visits only known subschema keywords, so an `$id`
  inside `enum`, `const` or an unknown keyword is data. Indexing and
  preparation use a queue rather than recursion.
- **Embedded meta-schemas.** The 2020-12 meta-schema and its seven
  vocabulary meta-schemas are compiled into the deck (generated by
  `tools/gen-meta.sh`), so a `$ref` to them resolves offline. They are
  indexed only when a schema refers to them.
- **Vocabularies per resource.** A resource's `$schema` decides its
  vocabularies (Core 8.1.1); a resource without one inherits from the
  resource that entered it. A meta-schema requiring an unknown vocabulary is
  refused at compile time.
- **`format` is an annotation by default**, as the specification says.
  `assertFormats` turns on the lenient mode: the 14 checked formats assert,
  any other name passes. A resource whose meta-schema lists the
  format-assertion vocabulary gets the strict mode: a format the deck does
  not check is refused at compile time, and an unknown name fails every
  value.
- **Patterns on RE2 with ECMA-262 meaning.** `\s`, `\S`, `.`, `\cX`,
  `\uXXXX` (a surrogate pair as one code point) and `\u{...}` are rewritten
  to their ECMA-262 meaning. A pattern RE2 cannot compile (lookaround, a
  backreference) is a schema error naming the keyword, never a silent
  non-match.
- **Exact numbers.** `1.0` is an integer. `multipleOf` is exact: integer
  remainder when both values are whole and fit 64 bits, otherwise decimal
  arithmetic on the shortest round-trip text; a float fallback remains only
  for an 18-digit whole divisor against a value past 2^63.
- **`uniqueItems` in one pass.** Each item is keyed by a text that is equal
  exactly when the JSON values are, so uniqueness is one map lookup per item.
- **Annotations for `unevaluated*`.** Each keyword returns its outcome with
  the properties and items it evaluated; `unevaluatedItems` and
  `unevaluatedProperties` run last on the merged annotations, and a failing
  outcome drops its annotations, as the specification requires.
- **An invalid instance never throws.** It yields issues. Only a schema the
  deck cannot use throws.
- **Messages** quote values and names cut to 60 characters.

## Errors

- An invalid instance is a `Result` with `Issue`s, never an error.
- A schema the deck cannot use is an `Error` of kind `"jsonschema"`
  (`ERROR_KIND`): at `compile` for an unknown required vocabulary or an
  unchecked format under the assertion vocabulary, and where evaluation
  reaches it for anything else (an unresolvable `$ref`, a pattern RE2 cannot
  compile, a `$ref` cycle).
- An instance nested so deeply that evaluation reaches the interpreter's
  call-depth limit throws that limit's error, kind `"limit"`, passed on
  unchanged through every helper and `validate` and `isValid`, so a caller
  tells a hostile instance from a broken schema by kind.

## Security and limits

- Nothing is fetched, so a schema cannot make the program reach the network
  or the file system.
- `$ref` cycles: 200 references in a row at the same instance location stop
  evaluation; moving into the instance resets the count.
- RE2 matches in linear time, so a hostile `pattern` cannot backtrack
  catastrophically.
- Deep instances end at the interpreter's call-depth limit (kind
  `"limit"`); documents are bounded first by `json.decode`'s nesting cap.
- There is no work budget: a large instance against a large schema costs
  time proportional to both (about 0.7 ms per record of five typed
  properties).

## Testing and validation

- 154 tests. Most coverage is the official JSON-Schema-Test-Suite for draft
  2020-12, vendored in `testdata/suite` with its commit pinned. Every case
  runs through both `isValid` and `validate`, and a disagreement or a throw
  counts as a failure. The suite's remote documents are registered under
  their test URLs.
- `testdata/exclusions.txt` lists every case the deck knowingly gets wrong,
  and each keyword's test asserts its file fails exactly those: a new
  failure breaks the build, and so does an exclusion that starts passing.
  Required: 46 files and 1302 cases, all passing. The known gaps are listed
  in [Conformance](conformance.md).
- A test binary-searches the call depth at which a check stops and asserts
  that the outcomes around it are only a pass or the depth error.
- The suite is not part of an installed deck; there its tests are skipped,
  and a separate test fails a repository run that lost it.
- `jennifer-tiny` has no test runner; an exported-API runner was diffed
  across both binaries. tiny's smaller call budget is why the evaluator's
  per-level path is kept short.

## Known limitations and open questions

- Older drafts, IDNA host names (`xn--` labels are not decoded) and
  ECMA-262-only syntax in the `regex` format are known gaps
  ([Conformance](conformance.md)).
- `idn-email`, `idn-hostname`, `iri`, `iri-reference` and `uri-template` are
  not checked.
- Interpretive overhead dominates: validating the meta-schema against three
  meta-schema documents a hundred times takes about 11 s. Each call from
  outside the deck rebuilds the `Schema` struct at the module boundary, so
  new `Schema` fields cost on every call.
- On interpreters where `json.typeOf` throws for a missing pointer instead
  of returning `"missing"`, the deck reads kinds through its own guard.

## Dependencies on the interpreter

- Floor `>=0.27.0`: the tests use `strings.replicate`, new in 0.27.0. No
  capabilities; not declared for `jennifer-tiny`, though the exported API
  gives the same results there.
- The bundled `uri` module for reference resolution, `json` pointer
  accessors, and `regex` on RE2.
- The interpreter's call-depth limit raised as kind `"limit"`, which the
  deck catches by kind.
